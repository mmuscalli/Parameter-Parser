# Pre-parse to leave out unused parameters (2026-11-08)

**Question (Mickey):** before a multi-paper run, can a cheap pre-parse find which of a research area's parameters the
papers report, switch the rest off, and save meaningfully if a few misses are acceptable?

**Method.** `preparse.py`: one Claude Haiku request per paper (text only) listing the area's stage parameters; the
parameters no paper reports go to `RunConfig.parameters_off` (dropped from the steps' prompts and answer schemas; a
step with none left doesn't run). Live A/B on the six reference papers, Standard models, each paper run in full and
pruned (different tool lists, so the two runs don't share a cache), scored against the reference CSVs with
`scripts/eval_references.score`.

| paper | params kept | full: accuracy / cost | pruned: accuracy / cost | pre-parse |
|---|---|---|---|---|
| eder1994 | 14/42 | 100% / $0.329 | 100% / $0.316 | $0.0023 |
| faisal2005 | 14/42 | 95.0% / $0.302 | 95.0% / $0.332 | $0.0026 |
| kim2017 | 6/42 | 100% / $0.234 | 88.9% / $0.186 | $0.0018 |
| kim2019 | 7/42 | 92.3% / $0.228 | 69.2% / $0.207 | $0.0022 |
| truman2024 | 13/42 | 100% / $0.265 | 95.5% / $0.265 | $0.0021 |
| aa57186 (exoplanets) | 0/45 (bug) | 98.1% / $0.318 | 19.3% / $0.174 | $0.0052 |

Prebiotic mean: **$0.272 -> $0.263 with the pre-parse (-3%)**, accuracy **97.5% -> 89.7%**. (The exoplanet run lost
everything to a bug -- the model copied whole listing lines as column names; fixed, but the conclusion doesn't depend
on it.)

**Why so little.** The parameters' own share of a run is small: pruning ~2/3 of them cut the cached prefix by ~2.3K of
~29K tokens (tool schemas and instructions shrink, but the paper dominates). Output tokens -- the biggest cost -- only
exist for values a paper has, so leaving out absent parameters saves no output; where output did drop (kim2017,
kim2019) it was values the run then missed. The misses are systematic: a pre-parse judges "does the paper state X",
but the run fills several parameters by rule or inference -- sampled_temperature_C (the heating temperature),
solvent_volume_mL (summed solution volumes), initial_temperature_C from a heating step -- and those were dropped.

**Decision.** Not wired into the app. Kept: `preparse.py` (evaluation tool), `RunConfig.parameters_off` (plumbing), and
a risk-free saving found on the way: a stage triggered by keywords alone (kinetics) whose words aren't in the paper no
longer sends its tool definition with a single paper's cached prefix (~3.6K tokens, ~$0.009 on Standard); in paper
queues the tool list stays fixed, because the cross-paper cache of shared instructions saves more (-17%).

Cheaper multi-paper runs come from the levers already measured: Balanced / Economy profiles, batch mode, shared
cached instructions (queues).
